# Data dictionary

This document describes the principal variables used in the canonical PV-validation datasets and analysis outputs.

Exact column availability may differ slightly between the annual and shading canonical datasets.

Units are stated explicitly wherever applicable.

---

## 1. Identification and time variables

| Variable | Unit / format | Description |
|---|---|---|
| `system` | categorical | PV system identifier: `A`, `B`, or `C`. |
| `timestamp` | datetime | Common analysis timestamp used to align measured, IDA ICE, and PVsyst data. |
| `analysis_timestamp` | datetime | Synthetic analysis time axis used where retained explicitly in the canonical dataset. |
| `physical_timestamp` | datetime | Timestamp representing the true June 2020–May 2021 measurement period; used for solar geometry. |
| `physical_day` | date | Physical calendar day derived from `physical_timestamp`; used in block-bootstrap and aggregation analyses. |
| `physical_month` | year-month | Physical calendar month used for monthly aggregation. |
| `kWp` | kWp | Nominal installed PV-system capacity. |

Not every derived time column is necessarily stored permanently in the base canonical CSV; some are generated by analysis scripts as needed.

---

## 2. Measured variables

| Variable | Unit | Description |
|---|---:|---|
| `GTI_measured_Wm2` | W/m² | Measured plane-of-array global irradiance used as the reference irradiance observation. |
| `Tp_measured_C` | °C | Measured PV panel/module temperature. |
| `P_measured_W` | W | Measured AC power output. |
| `Tamb_measured_C` | °C | Measured ambient temperature, where retained in the canonical dataset. |

### System A measured GTI

The System A measured GTI series includes the documented one-hour alignment correction applied during canonical-data reconstruction.

Systems B and C use the common measured GTI series without this correction.

---

## 3. IDA ICE variables

| Variable | Unit | Description |
|---|---:|---|
| `GTI_IDA_Wm2` | W/m² | IDA ICE panel effective irradiance output used for comparison with measured GTI. |
| `Tp_IDA_C` | °C | IDA ICE simulated panel temperature. |
| `P_IDA_W` | W | IDA ICE simulated AC power output. |

### Irradiance terminology

`GTI_IDA_Wm2` represents the closest available IDA ICE irradiance output used for the model comparison.

The software output is panel effective irradiance and should not be interpreted as necessarily identical in physical definition to an unmodified incident plane-of-array irradiance measurement.

---

## 4. PVsyst variables

| Variable | Unit | Description |
|---|---:|---|
| `GTI_PVsyst_Wm2` | W/m² | PVsyst `GlobEff` / effective irradiance output used for comparison with measured GTI. |
| `Tp_PVsyst_C` | °C | PVsyst array/module temperature output. |
| `P_PVsyst_W` | W | PVsyst simulated AC/grid power output. |

### PVsyst row-order provenance variables

Some canonical/sensitivity datasets may additionally contain:

| Variable | Unit / format | Description |
|---|---|---|
| `pvsyst_hour_index` | integer | Zero-based hourly row position in the original PVsyst export. |
| `pvsyst_timestamp_uncorrected` | datetime | Timestamp reconstructed from PVsyst row order before any documented timing correction. |
| `pvsyst_time_shift_h` | h | Uniform timing correction applied to the PVsyst record. |

For the corrected System A Engerer2 case:

```text
pvsyst_time_shift_h = +1
```

For Systems B and C:

```text
pvsyst_time_shift_h = 0
```

---

## 5. Solar-geometry variables

| Variable | Unit | Description |
|---|---:|---|
| `AOI_deg` | degrees | Solar angle of incidence on the PV plane. |
| `solar_zenith_deg` | degrees | Solar zenith angle, where retained. |
| `solar_azimuth_deg` | degrees | Solar azimuth angle, where retained. |
| `Eextn_Wm2` | W/m² | Extraterrestrial irradiance normal to the solar beam, where retained. |
| `Eextt_Wm2` | W/m² | Extraterrestrial irradiance projected onto the tilted PV plane, where retained. |
| `kt_tilt` | dimensionless | Tilted clearness index calculated from measured GTI and extraterrestrial irradiance on the tilted plane. |

The final solar-geometry calculation uses the full azimuth-dependent angle-of-incidence relationship.

---

## 6. Weather-condition classification

The weather-condition analysis classifies observations using `kt_tilt`.

| Category | Definition |
|---|---|
| Overcast / very cloudy | `kt_tilt < 0.20` |
| Cloudy | `0.20 ≤ kt_tilt < 0.40` |
| Mixed / broken | `0.40 ≤ kt_tilt < 0.60` |
| Mostly clear | `0.60 ≤ kt_tilt < 0.75` |
| Clear | `kt_tilt ≥ 0.75` |

Only observations with:

```text
AOI_deg < 80
```

are included in the primary weather-bin analysis.

No upper limit is applied to `kt_tilt`.

---

## 7. Residual definition

For all validation variables, the residual is defined as:

```text
residual = simulated - measured
```

Consequently:

```text
positive residual → simulation overestimates measurement
negative residual → simulation underestimates measurement
```

This sign convention is used consistently for IDA ICE and PVsyst.

---

## 8. Validation metrics

### RMSE

Root mean square error:

```text
RMSE = sqrt(mean((simulated - measured)^2))
```

Units are the same as the underlying variable.

Examples:

```text
GTI         W/m²
Temperature °C
Power       W
```

---

### CV(RMSE)

Coefficient of variation of RMSE:

```text
CV(RMSE) = RMSE / mean(measured) × 100
```

Unit:

```text
%
```

Used primarily for irradiance and AC power.

---

### MAE

Mean absolute error:

```text
MAE = mean(abs(simulated - measured))
```

---

### nMAE

Normalised mean absolute error:

```text
nMAE = MAE / mean(measured) × 100
```

Unit:

```text
%
```

---

### MBE

Mean bias error:

```text
MBE = mean(simulated - measured)
```

Positive values indicate average overprediction and negative values indicate average underprediction.

---

### nMBE

Normalised mean bias error:

```text
nMBE =
sum(simulated - measured)
/
sum(measured)
× 100
```

Unit:

```text
%
```

---

### RE

Relative error is calculated using the same aggregate error convention as the final nMBE implementation:

```text
RE =
sum(simulated - measured)
/
sum(measured)
× 100
```

Unit:

```text
%
```

---

### R²

Coefficient of determination calculated from measured and simulated observations.

---

## 9. Monthly energy variables

Hourly power values are integrated to energy by treating each hourly value as representing one hour.

Typical derived variables include:

| Variable | Unit | Description |
|---|---:|---|
| measured monthly energy | kWh/month | Sum of measured hourly AC power converted to energy. |
| IDA ICE monthly energy | kWh/month | Sum of IDA ICE hourly AC power. |
| PVsyst monthly energy | kWh/month | Sum of PVsyst hourly AC power. |
| monthly RMSE | kWh | RMSE across the 12 monthly energy totals. |
| monthly RMSE per kWp | kWh/kWp | Monthly energy RMSE normalised by installed capacity. |

---

## 10. Temporal aggregation variables

The temporal-aggregation sensitivity analysis uses the same cleaned hourly power records at three scales.

### Hourly

```text
Power [W]
```

### Daily

```text
Energy [kWh/day]
```

### Monthly

```text
Energy [kWh/month]
```

No sub-hourly simulation values are generated by this analysis.

---

## 11. Uncertainty-analysis variables

Typical uncertainty outputs include:

| Variable | Description |
|---|---|
| `Bootstrap95_low` | Lower 2.5th percentile of the moving-block bootstrap distribution. |
| `Bootstrap95_high` | Upper 97.5th percentile of the moving-block bootstrap distribution. |
| `Delta_RMSE_IDA_minus_PVsyst` | IDA ICE RMSE minus PVsyst RMSE. |
| `Delta_RMSE_CI95_low` | Lower bootstrap interval for the paired RMSE difference. |
| `Delta_RMSE_CI95_high` | Upper bootstrap interval for the paired RMSE difference. |
| `bootstrap_p_raw` | Unadjusted supplementary bootstrap p-value. |
| `bootstrap_p_Holm` | Holm-adjusted p-value across paired comparisons. |
| `Favored_by_RMSE` | Tool with the numerically lower RMSE. |

For:

```text
Delta_RMSE_IDA_minus_PVsyst
```

the sign convention is:

```text
negative → IDA ICE has lower RMSE
positive → PVsyst has lower RMSE
```

---

## 12. Measurement-uncertainty scenarios

The combined measurement/temporal uncertainty analysis evaluates:

```text
LOW
NOMINAL
HIGH
```

measurement scenarios.

The bounds are:

| Variable | Bound |
|---|---:|
| GTI | ±2% |
| AC power | ±1% |
| Panel temperature | ±0.5 °C |

The bounds are applied as systematic series-level perturbations rather than independent random noise at every timestamp.

---

## 13. Combined uncertainty envelope

The combined measurement-and-temporal uncertainty output uses:

```text
Combined_envelope_low
Combined_envelope_high
```

These represent the outer limits of the 30-day moving-block-bootstrap intervals obtained across the LOW, NOMINAL, and HIGH measurement scenarios.

They should be interpreted as:

> bootstrap uncertainty enveloped over stated measurement-uncertainty bounds

rather than as a fully probabilistic joint 95% confidence interval.

---

## 14. Shading variables

The shading canonical dataset contains aligned hourly values for:

- measured AC power;
- IDA ICE AC power;
- PVsyst AC power.

Additional shading provenance variables may indicate:

- shading-object configuration;
- source export;
- case-study day;
- system identifier.

The final shading analysis uses three periods:

```text
5 June 2023
15 May 2023
1 May – 19 June 2023
```

The exact timestamp-window definitions used in the analysis are implemented in the analysis scripts.

---

## 15. Missing values

Missing values are represented as:

```text
NaN
```

or blank spreadsheet cells in source files.

Paired comparisons use observations for which the required measured and simulated values are present.

Missing simulation values are not replaced through interpolation unless explicitly documented.

---

## 16. Daytime filtering

The annual validation uses daytime observations defined as:

```text
GTI_measured_Wm2 > 0
```

The daytime filter is applied using the measured irradiance reference rather than separate model-specific irradiance thresholds.

---

## 17. AC-power gross-error exclusions

Four timestamps are excluded from the annual AC-power analysis:

```text
2021-02-02 12:00
2021-02-02 13:00
2021-04-02 13:00
2021-04-30 13:00
```

These exclusions are applied as complete records so that:

- measured data;
- IDA ICE;
- PVsyst

retain identical comparison timestamps.

The exclusions do not apply to the GTI or panel-temperature validation.

---
