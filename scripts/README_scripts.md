# pv-validation-idaice-pvsyst
Reproducible data-processing, validation, uncertainty, sensitivity, and figure-generation workflow for comparing PV simulations in IDA ICE and PVsyst against measured data.

# Analysis scripts

This directory contains the Python scripts used to reconstruct the analysis datasets, reproduce the primary validation results, perform uncertainty and sensitivity analyses, and generate the manuscript figures and tables.

The scripts are numbered according to their approximate execution order. Diagnostic scripts used to investigate specific data-quality or provenance issues are stored separately in `audits/`.

## Recommended workflow

The main reproduction workflow is:

```text
00_check_inputs.py
        ↓
01_build_canonical_data.py
        ↓
02_run_analysis.py
        ↓
03_make_figure3_combined.py
        ↓
04_build_master_results.py
        ↓
05_statistical_uncertainty.py
        ↓
06_build_tables4_6_uncertainty.py
        ↓
07_reverse_transposition_sensitivity.py
        ↓
08_combined_measurement_temporal_uncertainty.py
        ↓
09_temporal_aggregation_sensitivity.py
        ↓
10_weather_bin_edge_sensitivity.py
        ↓
11_make_figures4_5_6_shading.py
```

Not every script must be rerun to inspect the published results. The canonical datasets can be used as a starting point for the main statistical analysis if the source-data reconstruction does not need to be repeated.

## Script descriptions

### `00_check_inputs.py`

Checks whether the source files required by the analysis are present in the expected directories.

This script should be run first after cloning the repository and adding any source files that are not distributed directly with the repository.

Typical checks include:

- measured annual data;
- measured shading data;
- IDA ICE exports;
- PVsyst exports;
- weather and irradiance-processing inputs;
- configuration files.

Run with:

```bash
python scripts/00_check_inputs.py
```

---

### `01_build_canonical_data.py`

Constructs the canonical annual and shading datasets from the original measured data and simulation exports.

This script performs the principal data-alignment and preprocessing operations required before statistical analysis.

The annual dataset includes aligned values for:

- measured variables;
- IDA ICE results;
- PVsyst results;
- solar geometry;
- tilted clearness index;
- analysis timestamps;
- physical timestamps.

Important preprocessing steps include the documented System A GTI alignment correction and the reconstruction of full azimuth-dependent solar geometry.

The canonical datasets generated by this script form the authoritative input to subsequent analysis scripts.

---

### `02_run_analysis.py`

Performs the primary validation analysis.

This script produces the main statistical results for:

- GTI/effective irradiance;
- panel temperature;
- AC power;
- monthly energy RMSE normalized by installed capacity;
- weather-condition performance;
- shading validation;
- power-exclusion auditing.

The annual power analysis excludes the four gross-error timestamps defined in `config.json`.

No residual outlier removal is applied to the GTI or panel-temperature analyses.

The primary annual analysis uses the Perez–Driesse irradiance reconstruction.

---

### `03_make_figure3_combined.py`

Generates the final combined Figure 3 showing model performance by weather condition.

The figure contains:

- CV(RMSE) by weather-condition bin;
- nMBE by weather-condition bin.

IDA ICE and PVsyst are distinguished using consistent colors and plotting styles.

The figure uses the finalized weather-bin results produced by the primary analysis and does not recalculate the validation metrics.

---

### `04_build_master_results.py`

Creates a consolidated results workbook containing the numerical results used in the manuscript.

The purpose of this script is to provide one auditable location for the values allowed to enter the article.

Outputs include results associated with:

- annual GTI validation;
- panel-temperature validation;
- annual AC-power validation;
- monthly RMSE;
- weather-condition analysis;
- shading analysis.

This file is useful for cross-checking manuscript tables and figures.

---

### `05_statistical_uncertainty.py`

Performs the primary statistical uncertainty analysis.

Because hourly PV data are temporally autocorrelated, uncertainty intervals are estimated using a moving-block bootstrap rather than an independent-observation bootstrap.

The analysis includes:

- autocorrelation diagnostics;
- block-length sensitivity;
- annual bootstrap confidence intervals;
- paired IDA ICE versus PVsyst RMSE comparisons;
- Holm-adjusted supplementary p-values;
- sensitivity to the four excluded power timestamps;
- weather-bin uncertainty;
- shading uncertainty.

A 30-day block length is used as the primary annual inference setting.

Shorter block lengths are included to assess sensitivity to the assumed temporal dependence.

---

### `06_build_tables4_6_uncertainty.py`

Combines the principal annual validation metrics with uncertainty results for manuscript Tables 4–6.

This script adds uncertainty information without replacing the original point estimates.

Paired statistical inference is associated with the RMSE comparison between IDA ICE and PVsyst rather than with unrelated metrics such as nMBE.

---

### `07_reverse_transposition_sensitivity.py`

Evaluates sensitivity to the irradiance reverse-transposition/separation method.

The primary analysis uses Perez–Driesse.

This script constructs and evaluates an alternative Engerer2 scenario using otherwise identical:

- measured data;
- timestamps;
- geometry;
- filtering;
- power exclusions;
- statistical definitions.

The script also compares the IDA ICE versus PVsyst conclusions between Perez–Driesse and Engerer2.

#### System A Engerer2 PVsyst timing correction

A reproducibility audit identified a consistent one-hour displacement in the System A Engerer2 PVsyst export.

The displacement affected:

- effective irradiance;
- panel temperature;
- AC power.

The entire System A Engerer2 PVsyst record is therefore shifted uniformly by +1 h before comparison.

No scaling, interpolation, or variable-specific adjustment is applied.

Systems B and C are not shifted.

See the scripts in `audits/` and `docs/DATA_PROVENANCE.md` for details.

---

### `08_combined_measurement_temporal_uncertainty.py`

Combines measurement uncertainty bounds with temporal bootstrap uncertainty.

The stated measurement uncertainty bounds are treated as systematic sensitivity scenarios rather than as assumed probability distributions:

```text
GTI                ±2%
AC power           ±1%
Panel temperature  ±0.5 °C
```

For each low, nominal, and high measurement scenario, the analysis applies the 30-day moving-block bootstrap.

The outer limits of the resulting bootstrap intervals are reported as a combined measurement-and-temporal uncertainty envelope.

These envelopes should not be interpreted as fully probabilistic joint 95% confidence intervals.

The analysis is performed for both:

- Perez–Driesse;
- Engerer2.

---

### `09_temporal_aggregation_sensitivity.py`

Tests whether conclusions about relative IDA ICE and PVsyst performance depend on the temporal scale of evaluation.

The finalized hourly AC-power records are evaluated as:

```text
Hourly   → power [W]
Daily    → energy [kWh/day]
Monthly  → energy [kWh/month]
```

The script compares RMSE, CV(RMSE), bias, and tool ranking at each aggregation level.

This analysis aggregates the common hourly results. It does not generate sub-hourly simulations.

The PVsyst version available for the study was limited to hourly simulation output, so a matched sub-hourly IDA ICE/PVsyst comparison could not be performed.

---

### `10_weather_bin_edge_sensitivity.py`

Tests whether the qualitative weather-condition conclusions depend on the exact tilted-clearness-index thresholds.

The nominal internal bin boundaries are shifted by ±0.05:

- simultaneously;
- one boundary at a time.

The script evaluates whether changes in the bin definitions affect:

- CV(RMSE);
- nMBE;
- sample counts;
- IDA ICE versus PVsyst ranking;
- the overall cloudiest-to-clearest error pattern.

The analysis does not alter the underlying `kt_tilt` values or simulation results.

---

### `12_make_figures4_5_6_shading.py`

Generates the time-series plots used for the shading figures.

Each system is presented for:

- 5 June 2023 — clear case;
- 15 May 2023 — partly cloudy case.

The plotted series are:

- measured AC power;
- IDA ICE AC power;
- PVsyst AC power.

The plotting styles are designed to remain distinguishable in both color and black-and-white printing.

The script exports both combined figures and individual panels so that IDA ICE screenshots or other graphical material can be inserted between the plots during manuscript layout.

## Audit scripts

The `audits/` directory contains scripts used to investigate specific reproducibility issues.

These scripts are retained because they document why particular preprocessing decisions were made, but they are not required for routine reproduction of the final manuscript results.

### `07a_audit_Engerer2_SystemA_GTI.py`

Investigates the unusually large System A GTI discrepancy originally observed in the Engerer2/PVsyst sensitivity case.

The analysis compares:

- Perez–Driesse and Engerer2;
- IDA ICE and PVsyst;
- zero-lag and shifted alignments.

---

### `07b_audit_PVsyst_clock_and_lag.py`

Tests possible temporal offsets in the PVsyst outputs.

The audit showed that all three System A Engerer2 PVsyst variables preferred the same +1 h shift, while the corresponding Perez–Driesse results and Systems B and C did not.

This supported treatment of the issue as a uniform record displacement rather than independent variable corrections.

---

### `07c_audit_PVsyst_export_metadata.py`

Examines workbook metadata and embedded file references from the PVsyst exports.

The audit identified a unique meteorological-file reference for the System A Engerer2 simulation:

```text
Ekås_Custom_E2.MET
```

The original `.MET` file was no longer available.

The metadata audit provides an independent provenance clue supporting the System A Engerer2 timing investigation.

## Configuration

Shared analysis settings are stored in:

```text
config.json
```

Scripts should use the configuration file rather than duplicating frozen methodological settings internally wherever possible.

The configuration includes information such as:

- site geometry;
- timezone;
- weather-bin thresholds;
- AOI limit;
- predefined power exclusions.

## Reproducibility principle

The active scripts in this directory represent the finalized analysis workflow.

Superseded scripts and earlier experimental analysis approaches are kept under `archive/` rather than mixed with the active workflow.

When results differ between archived analyses and the active scripts, the outputs produced by the active workflow should be treated as authoritative.
