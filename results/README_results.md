# pv-validation-idaice-pvsyst
Reproducible data-processing, validation, uncertainty, sensitivity, and figure-generation workflow for comparing PV simulations in IDA ICE and PVsyst against measured data.
# Results

This directory contains the generated numerical results, uncertainty analyses, sensitivity analyses, and publication figures produced by the reproducible Python workflow in this repository.

The files in this directory are **generated outputs**. They should not be edited manually to alter analysis results.

If an analysis result must be changed, the relevant source data, configuration, or analysis script should be corrected and the corresponding output regenerated.

---

## 1. Primary analysis

The principal annual validation results are generated by:

```bash
python scripts/02_run_analysis.py
```

The primary annual analysis uses the **Perez–Driesse irradiance reconstruction**.

The main files are:


### `Table4_GTI_recomputed.csv`

Contains the annual irradiance-validation metrics for Systems A, B, and C for IDA ICE and PVsyst.

Reported metrics include:

- RMSE;
- MAE;
- CV(RMSE);
- nMAE;
- MBE;
- nMBE;
- relative error;
- R².

No residual outliers are removed from the irradiance analysis.

---

### `Table5_Temperature_recomputed.csv`

Contains the annual panel-temperature validation results.

No residual outliers are removed from the panel-temperature analysis.

---

### `Table6_Power_recomputed.csv`

Contains the annual AC-power validation results.

The annual power analysis uses daytime observations and excludes the four predefined gross-error timestamps documented in:

```text
config.json
docs/METHODS.md
docs/DATA_PROVENANCE.md
```

The table contains both hourly validation metrics and monthly RMSE normalized by installed PV capacity.

---

### `Monthly_RMSE_recomputed.csv`

Contains monthly-energy RMSE values for each system and simulation tool.

The reported normalized quantity is:

```text
kWh/kWp
```

and is calculated from the twelve monthly energy totals.

---

### `Figure3_weather_bins_recomputed.csv`

Contains the nominal weather-condition analysis used to generate Figure 3.

The weather classes are based on tilted clearness index, `kt_tilt`, using the thresholds defined in:

```text
config.json
```

The final weather-bin analysis also applies:

```text
AOI < 80°
```

and does not impose an upper limit on `kt_tilt` for the clear-sky category.

## 3. Statistical uncertainty

Files beginning with:

```text

```

```bash
python scripts/05_statistical_uncertainty.py
```

The primary annual statistical inference uses:

Important files include:

```text

05_ACF_paired_loss_difference.csv
05_STATISTICAL_INFERENCE.xlsx
```

### Paired model comparison

The paired comparison is based on:

```text
ΔRMSE = RMSE_IDA ICE - RMSE_PVsyst
```

Therefore:

```text
ΔRMSE < 0  → lower RMSE for IDA ICE
ΔRMSE > 0  → lower RMSE for PVsyst
```

The primary interpretation is based on the estimated difference and its bootstrap confidence interval.

Holm-adjusted bootstrap p-values are provided as supplementary inferential information.

## 6. Combined measurement and temporal uncertainty

The directory:

```text
uncertainty/
```

contains the analysis generated by:

```bash
python scripts/08_combined_measurement_temporal_uncertainty.py
```

Measurement uncertainty is evaluated using bounded scenarios for:

```text
GTI          ±2 %
AC power     ±1 %
Temperature  ±0.5 °C
```

These scenarios are combined with the 30-day moving-block bootstrap.

The reported combined interval is an **uncertainty envelope** formed from the outer bootstrap limits across the measurement scenarios. It should not be interpreted as a fully probabilistic joint 95% confidence interval.

Important files include:

```text
08_Measurement_scenario_metrics.csv
08_Paired_comparison_by_measurement_scenario.csv
08_Paired_comparison_combined_envelope.csv
08_Combined_metric_envelope.csv
08_Combined_uncertainty_summary.csv

```

## 12. Editing policy

Generated result files should not be manually altered.

If a correction is required:

1. identify the relevant source-data, configuration, or analysis issue;
2. update the appropriate script or source;
3. regenerate the affected canonical data if required;
4. rerun the downstream analysis;
5. commit the script change and regenerated results together.

This preserves the audit trail between source data, analysis code, and published results.

## 13. Versioning

Results used in a manuscript or publication should correspond to a specific Git commit, release, or archival DOI.

Once the associated article is published, the repository release and publication DOI should be recorded here.
